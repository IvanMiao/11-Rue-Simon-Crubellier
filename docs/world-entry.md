# 进入世界：原著研究 + 反馈层重设计

> 资料：法语维基 *La Vie mode d'emploi*、*Liste des personnages de La Vie mode d'emploi*、*Polygraphie du cavalier*、*Carré gréco-latin*，Commons 上的楼层平面图（Plan immeuble VME final）和骑士巡游动画（Lavida animacion），vme-web.fr（Christel Lidl 的研究站）。
> 10×10 方格的章节号、住户和骑士路线已经写成数据，见 `world/damier.ts`；1→99 的跳法有测试校验。

## 一、原著事实（已核实）

1. **整本书是一幅画的描述**：瓦莱纳想画整栋楼的剖面，画面停在 1975 年 6 月 23 日快到 20 点的那一刻。全书是“一分钟被荒诞地拉长”（monstrueuse dilatation d'une minute）。99 章每章写**一间临街的房间（pièce）**，不是一整套公寓。
2. **10×10 方格**：竖向是地下室、底层、6 层公寓、2 层女仆房，一共 10 层；每层 10 格。一套公寓占好几格，比如巴特尔布思占 3 层左边 5 格，对应第 99、70、26、80、87 章。我们 `constants.ts` 里的公寓划分和原著平面图一致，但原著的最小单位是**格 / 间**，我们的是**公寓**。
3. **骑士巡游（polygraphie du cavalier）**决定章节顺序。第 1 章在 3 层楼梯间（“Dans l'escalier”），第 2 章是博蒙家，第 3 章是富罗家。我校验过：98 次连续移动里只有 **65 → 66** 不是骑士跳，因为左下角那格（地下室最左）从来没去过，这就是书只有 99 章的原因。
   - **更正我之前的说法**：并没有“缺掉的第 66 章”。缺的是**第 100 格**，位置在第 65 章和第 66 章之间。Perec 说是第 65 章末尾那个啃小黄油饼干（petit-beurre）一角的小女孩“咬掉了”这一格，用来打破对称、藏起结构。
   - 6 个部分：Perec 说骑士每碰齐方格四条边就开始新的一部分。我按这条规则自己推算出的分界和“六部分”对不上，所以这一点没有核实。
4. **希腊-拉丁方（bi-carré latin orthogonal d'ordre 10）+ 42 张清单**：42 个主题两两配对，填进 21 个 10 阶正交拉丁方，再用 pseudo-quenine 打乱。每一格（每一章）因此得到 42 个必须写进去的元素，例如：姿势（跪、坐、爬、举一只手……）、活动（画画、整理、读写、修理……）、引文、一幅名画、一本书、墙上的东西（素墙 / 水彩 / 地图 / 照片……）、情感、动机（ressort：收到一封信、解开一个谜、策划一场报复……）、家具、颜色、材质、形状……
   - 原文例子，第 71 章：趴着 / 交谈 / 卡夫卡 / 鲁博 / 2 人 / 朋友 / 药房传单 / 沉浸在怀旧里 / 亮面漆 / 拼花地板 / ……
5. **Cahier des charges**（1993 年出版的手稿）：每章一页，列出这 42 个元素，**写进去一个就勾掉一个**。Perec 的厨房就是一张逐格勾选的清单。
6. **Clinamen（故意的偏差）**：42 个元素里有两项专门作用于清单本身。“Faux（假）”要求把某一项改掉，“Manque（缺）”要求删掉某一项。所以每章实际只写 41 项，而且其中一项是被改过的。另外，每章都要写进一个两位数，就是这一格在方格里的坐标。
7. **附录里的平面图**只写住户名字，不画房间，不标楼层，也不标方格和骑士路线。研究者说它是读者的“空间索引”：怎么串起散落的故事，要读者自己完成。
8. **结局**：巴特尔布思死在第 439 幅拼图前，桌上缺的洞是 X 形，他手里那块是 W 形。瓦莱纳几周后去世，画布几乎是空白的：只有炭笔打好的方格，“一栋楼的剖面草图，再也不会有人住进去”。
9. **对案件有用的原著细节**：
   - 诺谢尔太太有丹尼维尔医生开的证明，说她的腿爬不了楼梯，所以她从不把信送上女仆层。这是天然的不在场 / 戳穿谎言证据。
   - 莫雷莱在 1975 年已经**不住**八楼了：几次爆炸后，邻居普拉萨尔一家拿走了他的房间。
   - 斯莫特在练心算阶乘。
   - 玛西亚太太分不清哪些是要卖的家具、哪些是自己用的，总在店、公寓、后间和地窖之间搬家具。

## 二、诊断：为什么“进不去”

现在的界面是：一张公寓方格网 + 一栏网页文字 + 一个弹窗案卷。玩家看不到三条因果链：
- **我在哪、这里是什么**：进房间只换了一段文字，世界本身没有变化；
- **我能做什么、为什么不能**：按钮出现或消失，没有原因；
- **我拿到的东西从哪来**：卡出现在案卷里，没有出处，案卷本身也像是凭空给的。

原著恰好给每条链都准备了现成的、符合世界观的载体：**画布**（地图）、**章节**（进房间）、**清单（cahier）**（物件和行动）、**索引**（出处）。

## 三、方案：玩家是“读这本书的人”，界面是瓦莱纳的画室

### 1. 入口（替代角色创建表单）
- 开场是瓦莱纳的画室：一块方形画布，上面只有炭笔画的 10×10 方格（尾声原文）。
- 画外音是“拼图的艺术”这篇序言的一两句：单看一块拼图毫无意义，意义只在它和其它块的连接里。
- 玩家“翻开”这本书，三种原型改为三种**读法 / mode d'emploi**（棋手 = 按结构读，目录学家 = 按索引读，通灵者 = 按故事读），属性配点照旧。
- 第一步固定落在**第 1 章 · 楼梯间（3 层）**，而不是大厅。

### 2. 地图 = 画布（进房间的反馈）
- 主画面是剖面楼，每一格开局是**炭笔素描状态**（线稿、无色）。进入一格，这一格就被“画上”：上色、点灯、人物出现，镜头推进。
- 这样“进房间”本身就有可见的世界变化，楼也会随着这一局被一点点画满。
- 每格角上有一个淡淡的原著章节号。按原著顺序连续骑士跳的路线会被描成红线，这就是骑士 combo 的视觉化。
- 左下角那格永远是黑的（小女孩咬掉的那一角）。这里是**终局房**，取代现在虚构的 `100-1` 楼层。至少锁定 2 组之后，这一格才出现门。

### 3. 进房间 = 一章的标题页
- 原著章名格式是“住户名, n”。进房间时先出一张标题卡，例如“第 XXVI 章 · 巴特尔布思, 2 · 20:14”，然后才是这一间的内容。
- 标题卡下面显示这一间的**清单页**进度，例如“本页 0/5”。

### 4. 每一间 = 一页 cahier des charges（物件分类 + 能 / 不能做的原因）
每间房有一页清单，5–7 行，对应原著的主题：姿势 / 活动 / 墙上的东西 / 一件物件 / 一本书或一幅画 / 情感 / 动机。每一行就是一个可以互动的东西，状态分四种，一眼看清：
- ☐ **可看**：花 N 分钟，必定成功，勾掉这一行，给出一张卡或一段描写；
- ◇ **可检定**：写明“捷径：感知 9+，成功率 ~60%”，同时写出**另一条路**，例如“或者：切割笔记 + X 形 联想”；
- ▣ **锁住**：写明原因，例如“需要门房的钥匙串”“21:00 以后”“需要先拿到『讣告』卡”“意志不足”；
- ☑ **已完成**：打勾，并写出给了什么卡。

装饰性的物件不进清单，只出现在画面里，所以“能点的东西”一定有用。
**Faux / Manque 成为案件机制**：说谎者那一间的清单里有一行被画了波浪线，表示“这一行写的是假的”（Faux），这就是要戳穿的证词。巴特尔布思那一页永远缺一行（Manque），就是那块拼图。原著的结构规则直接变成推理线索。

### 5. 案卷 = 瓦莱纳的笔记本（出处）
- 案卷不是凭空出现的。第 1 章楼梯间里，瓦莱纳把他的笔记本交给你（或者你在楼梯上捡到），这是开局的第一个互动，也是教学：“他要画下这栋楼，但他记不全，帮他记。”
- 每张卡都带**出处脚注**，用原著索引的格式，例如“W 形 — XXVI（巴特尔布思, 2）· 检定失败所得”。点脚注，镜头就飞回那一格。
- 案卷最后一页是**原著那种平面图**：只有名字、没有楼层，随着玩家去过的格子一格一格填出来。

### 6. 检定 = 在清单的一行上落笔
- 检定前先摊开那一行：它属于哪一格、因为什么物件才能做、要花多少时间、失败会怎样（“失败也给一张卡，但可能是误导的”）。
- 掷骰时出现握骰子的手。结果直接写在那一行上：成功打勾，失败画一条斜线并写上得到的卡。
- 结果由引擎决定（同一个种子同一个结果），动画只是演出。

### 7. 事件反馈对照表（每个引擎事件都要有对应的世界内反馈）
| 引擎事件 | 世界内反馈 |
|---|---|
| `moved`（骑士） | 棋子走 L 形，镜头跟随；如果顺着原著路线，就描红线并显示 combo 数 |
| 进入新格 | 炭笔格被上色 + 章节标题卡 |
| `cardsFound` | 卡从物件位置飞进笔记本，带出处脚注 |
| `checkRolled` | 清单那一行展开，手 + 骰子，结果写回那一行 |
| `combined` | 两张卡在笔记本里贴在一起，生成新卡（失败时两张卡弹开，写一句原因） |
| `groupLocked` / `groupRejected` | 案卷板上盖章 / 撕掉一角并扣 1 点意志 |
| `rejected` | 不允许“点了没反应”：按钮本来就会写明锁住的原因，事件会把原因再说一遍 |
| 整点 | 楼里所有已上色的格子换一次光线，钟敲一下，新解锁的清单行闪一下 |

## 四、对引擎和计划的影响

- **新增纯函数 selector**（不改规则，只改可见性）：
  - `roomSheet(state, roomId)`：返回清单行和每行状态；
  - `actionAvailability(state, id)`：返回 `{ ok, reason }`，reason 是有类型的（`needsItem` / `notBefore` / `needsCard` / `noMorale` / `alreadyDone`……）。
  - UI 不自己判断，只显示 selector 给出的原因。这条最关键，它直接回答“为什么能 / 不能”。
- **每张卡记录出处**：`CaseState` 里记录每张卡来自哪个 `evidenceId` 或 `recipeId`。这会进入 action log，存档版本要 +1。
- **第 100 间改为 `-1-1`**，删掉 `100-1`：小改动，但要迁移旧存档。
- **以格为单位还是以公寓为单位**：这是需要你决定的大问题，见下。
- 正在写的 M3 规则（骑士 combo、整点、钥匙、默念、思想取舍）大部分不受影响：combo 换成“按原著路线”的版本，只改一个判断条件。

## 五、已定的决定（2026-10）

1. **以格为单位**：原著的 100 格就是游戏里的 100 间。99 格可以进入；左下角 `-1:1` 是终局格（clinamen），骑士永远跳不进去，锁定两组之后才能从相邻格走进去。
2. **保留 20:00→24:00 的时钟**：整点改成“画布换光”，规则不变。
3. **先做入口原型**：画室 → 第 1 章楼梯间 → 拾起瓦莱纳的速写本（也就是案卷） → 巴特尔布思家的第一页清单。
