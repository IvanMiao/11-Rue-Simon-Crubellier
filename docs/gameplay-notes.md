# 文学冒险 Roguelike：游戏性笔记

本文是设计讨论的存档，不是实现清单。对象是西蒙-克吕贝里埃街 11 号：佩雷克式网格 + 极乐迪斯科式检定 + 一局一种子。

核心判断：**这游戏不该换成 Unity/Godot 才能变好。** 它该变成一个“有运行时的文学引擎”——规则、内容原子、音频、画像都是数据；LLM 只在少数时刻当作家，不当地下城主。

---

## 1. 为了更好的游戏效果，框架和库该动什么

现在的骨架（React + Vite + 一次一次问 Gemini）适合做阅读器，不适合做“一局游戏”。玩家每点一个房间，体验就停在转圈上；规则写在组件里，内容写在提示词里，失败没有手感。

### 不要换游戏引擎

极乐迪斯科的身体是走路和油画。这栋楼的身体是剖面图、清单和检定。Phaser / Pixi 只在一种情况下值得上：地图要从 CSS 格子变成可缩放的建筑剖视图，并且房间里要有可点的静物。那是渲染层，不是重写项目。

### 要补的是游戏运行时，不是新 UI 框架

按收益排序：

1. **状态机。** 把一局收成明确状态：创角、织圣经、在楼里、检定中、终局。这些若散在 React 组件里，检定、时间、移动很容易互相打架。
2. **内容先是表，再是文章。** 房间、住户、线索、检定槽，应该是带 ID 的数据（YAML / JSON，或 Ink / Yarn 那种节点）。LLM 填写字段，不要每次直接写散文，再从散文里猜规则。
3. **骰子、移动、时间、意志、情节旗标必须本地、毫秒级。** 这些一旦等网络，游戏感会立刻死。
4. **音频独立一层**（Web Audio 或 Howler 一类）。不要在 React 里 `new Audio()` 凑合。音乐和检定音效是节奏，不是装饰。
5. **动效用时间轴**（GSAP 一类就够）：骰子、骑士跳、翻页、意志被削，必须有 300–800ms 的仪式。没有仪式，2d6 只是一次算术。
6. **存档存「种子 + 玩家选择序列」**，而不是整个 React state。这样才能重放一局、修 bug、做录像。`localStorage` 当原型可以；正式一点用 IndexedDB。

库的层面，真正有用的是：**状态机、内容脚本、音频、动画、种子随机**。换 Tailwind、换 React 版本、换一个 LLM SDK，对游戏性几乎没帮助。

一句话：把项目从“会写故事的网页”改成“会演一局故事的机”。LLM 是雇来的作家，不是引擎。

## 2. 故事圣经和房间：何时 LLM，何时脚本

边界应该狠。否则会做成 AI Dungeon：句子漂亮，世界不记得自己。

### 永远脚本（本地、可复现、玩家等不及）

- 能不能走进这个房间
- 2d6 出多少、成功还是失败
- 时间走了几分钟、意志掉没掉
- 哪条情节线处于传闻 / 进行 / 解决
- 谁今晚在家（由种子查表）
- 这一间房的骨架：张力高不高、桌上有什么类别的物件、能推进哪条线、有几个检定槽、难度大概多少

这些构成手感。玩家点下去，必须立刻有骰子、脚步、门开。

### 只在开局用一次 LLM（可以慢，必须藏在仪式后面）

故事圣经、本局人物关系、三条缠在一起的线、你为什么在 20:00 被放进来、思想柜里那三个念头。

创角本身就是一段阅读。3–8 秒的“为这一局编织圣经”可以接受，甚至应该做成演出：打字机、楼的剖面慢慢亮起、种子显示出来。**钱和耐心都花在这里。** 一次生成，整局受用。最好连带着出一份「房间任务卡」：每个重要房间只需约 80 字以内的秘密、在场者、两三个检定意图。不必把七十个房间的全文一次写完。

### 房间正文：不要在走进去的那一帧才请模型写小说

点房间 → 转圈 → 出 150 字，是最大的流畅度杀手。更稳的分层：

1. **立刻（约 0ms）。** 脚本拼出骨架。灯光、物件名单、谁在、检定按钮、一句本地的技能独白（「感知 — 茶已经不冒热气。」）。玩家已经在玩了。
2. **300–1500ms。** 如果有预写或缓存，把正文“打字”出来。这是翻书，不是加载。
3. **后台。** 只对“本局很可能走到”的房间预写正文（当前层相邻 + 骑士跳落点，大约 5–8 间）。玩家在读这一间时，下一间已经在织。
4. **走进去才现写。** 只留给真正冷门、种子事先没覆盖的格子。要有垫场，不能白屏转圈。

### 检定的成功 / 失败文本

优先在房间卡里预写两支。点下去只播骰子，然后揭晓。这是极乐迪斯科的节奏。

只有“世界被玩家改乱了、预写对不上”时，才当场写一段——而且先播机械结果（线索进案卷、意志 -1），句子随后跟上。玩家可以先看数字，再看散文。

### 延迟预算

| 动作 | 可接受等待 | 谁来做 |
| --- | --- | --- |
| 走路、开门、骰子 | < 100ms | 脚本 |
| 技能开口（短句） | 立刻，用本地句库 | 脚本 |
| 房间正文 | 感觉上像翻页，实际 < 1.5s | 开局 / 邻房预写 |
| 织本局圣经 | 3–8s，且必须有演出 | LLM 一次 |
| 点一个互动还要等模型 | 基本不可接受 | 不要 |

品味上的硬边界：**规则结果绝不能让模型改。** 模型可以解释“你失败了看见什么”，不能决定“你失败了吗”。否则种子、Roguelike、公平感全碎。

LLM 负责气味和句子；脚本负责因果和节奏。两者抢同一时刻，一定是句子赢、游戏输。

## 3. 美术资产、角色塑造、风格

要有美术。但不要做成“有立绘的文字冒险”，更不要做成像素 RPG。这栋楼的视觉主角是**剖面**，不是行走的小人。

极乐迪斯科的人是油画头像 + 思想是物体。佩雷克的人是房间里的物：纽扣、邮票、没下完的棋。角色应该同时是这两种：一张脸，加一份不会动的静物清单。

### 角色怎么塑造（先于画风）

- 每个重要住户三件套：**窗里的剪影**（地图尺度）、**半身像**（对话 / 检定时）、**三件物**（他留给世界的证据）。玩家先记住“六楼那扇黄灯 + 一副指纹没擦的眼镜”，再记住名字。
- 玩家自己也要有一张会被这栋楼磨损的脸。创角不要 3D 捏人，给 4–5 个职业剪影（目录学家的口袋、通灵者的黑眼圈、棋手的手套），再用种子在本局里“弄脏”它：灰尘、创可贴、被蒸汽烫过的领口。
- 不要追求走路动画。人在 20:00 是冻结的。动的是你的视线、骑士跳、电梯指示灯。冻结本身就是美术概念。

### 风格锚点

不是像素，不是二次元，不是写实照片。更接近：

- 佩雷克原书那种建筑剖面 / 克里斯·韦尔式图表
- 1975 年巴黎的褪色 Kodachrome
- 极乐迪斯科的油彩，但再干一点、更纸、更档案
- 打字机色带、硫酸纸、邮票齿孔

主色就是已经在用的温纸和石头色。检定用技能色点一下（共情粉、约束金），不要把界面涂成游戏 HUD。地图若升级，做成一张能慢慢看的剖面插画：混凝土、管道、各家不同的灯色。骑士跳落点不要金框，改成棋盘格上的一枚马。

### 资产策略

不要在运行时让模型生图。风格会漂、延迟会炸、角色会每局换脸。

该做的是**封闭图库 + 种子拼装**：约 20 张住户脸、10 种窗、30 件静物、几张剖面层。本局圣经只是在这些原子里拣人、换灯、给物件写标签。Wildermyth 那条路，不是每房一张生成图。

有没有美术，游戏性差很多：空间记忆、人物记忆、检定仪式，全靠图才能进长期记忆。但图必须服务于“列举”和“冻结”，而不是服务于“我是一个可操作角色”。

## 4. 音乐

要，而且比更多房间更优先。极乐迪斯科没有那层城市爵士，技能检定只是菜单。这栋楼没有声音，骑士跳只是换格子。

不要一上来做一张概念专辑。先做**建筑的声音设计**，再让它偶尔成为音乐。

- **基底。** 20:00 停住的世界。水管、电梯井、远处某家没关紧的收音机底噪。时钟指针不走，这是第一条音乐规则。
- **分层。** 阁楼干、中产层有一点走调钢琴、地窖是锅炉。随楼层混合，不要切歌。
- **检定。** 必须有专属一击。骰子落地、成功时和声打开、失败时气声被抽走。这是手感的一半。
- **骑士跳。** 棋子落盘 + 很短的 harmonic lift（叙事里的超清醒）。玩家会为了听这个去跳，比为了数值去跳更像游戏。
- **午夜。** 整局唯一一次真正的滴答。时间恢复流动，应该让人起鸡皮。
- **静。** 低张力的“普通房间”要更静。佩雷克的次日常如果一直配史诗垫乐，就假了。意志低时才加不协和，内境高时才让物件“出声”。

版权上不要直接塞 1975 年的法国流行歌。要么原作，要么做一段听起来像隔壁收音机的拟态。一首能循环的“井里的歌”够用很久。

技术上用分轨（drone / 楼层 / 收音机 / stings），按状态混合。一个四分钟 MP3 循环会很快被听穿，也会在读长段落时抢注意力。阅读时要会躲（ducking）。

## 合在一起的优先级

如果只做接下来最值的一层，顺序是：

1. 规则与内容原子本地化，LLM 退到开局和预写
2. 检定 / 移动的声音和约 0.5 秒仪式
3. 剖面图 + 头像 / 静物的封闭美术
4. 再考虑换渲染引擎

游戏性来自**何时等待、等待时身体在做什么**。现在玩家等待的是模型；理想情况是玩家等待骰子、等待一页纸翻过来、等待水管里那一声。句子可以晚一点到。因果必须准时。
